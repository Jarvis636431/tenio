# Projects Module

## 职责

`ProjectsModule` 负责项目主实体及其基础查询。

对应代码：

- `apps/api/src/modules/projects/*`

当前职责包括：

- 项目列表
- 项目详情
- 项目创建
- 项目与当前登录用户归属绑定

## 为什么这样设计

项目是后续上传、生成、工作台、agent 的业务容器。

因此项目模块必须满足两个条件：

1. 项目归属于当前用户
2. 项目成为其他模块的上游上下文

现在把 `projects` 放在 `auth` 之后，是因为没有用户态，后面的文件和生成都没有归属边界。

## 优点

- 项目已经从 mock 切到 PostgreSQL
- 项目天然带用户归属
- 后续 files / generation / artifacts 都可以挂在 `projectId` 下

## 缺点

- 当前字段还偏精简
- 暂未做协作成员、多租户、组织空间
- 暂未做复杂筛选和排序

## 可选方案

### 上传时隐式创建项目

优点：

- 前端入口可以少一步

缺点：

- 项目和文件边界会混乱
- 草稿项目、分批上传、失败恢复都难做

### 先只做文件，不引入项目容器

优点：

- 早期接口更少

缺点：

- 后续 generation、artifact、workbench 都缺少统一上下文

## 当前结论

先建立 `Project` 主实体是正确顺序。它是上传域、生成域和工作台域的最上游容器，不应该被省掉。
